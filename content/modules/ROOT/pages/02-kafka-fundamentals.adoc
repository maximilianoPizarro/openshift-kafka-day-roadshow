== Kafka Architecture on OpenShift

The workshop uses **Red Hat AMQ Streams** (Apache Kafka 4.2, based on Strimzi) running in **KRaft mode** (no ZooKeeper).

A *topic* is a named log of messages. A *partition* is a slice of that log so Kafka can scale reads and writes. *Replicas* are copies of a partition across brokers for durability.

You are here: Kafka and the Kafka Console. PostgreSQL and Debezium stay gray until the next modules.

== CLI: Produce Messages

You can produce messages directly from the command line. The client pod runs in your own namespace, `$(oc whoami)-workshop`, so it does not collide with the other participants. Kafka is reached with the cluster DNS name.

Send a few messages. The producer reads them from standard input and exits when the input ends. Do not stop it with `Ctrl+C`: that closes the `oc` session and prints `EOF` plus `terminated (Error)` even after Kafka has stored the records.

[source,bash,role="execute",subs="+attributes"]
----
printf '%s\n' \
  'Hello from the Kafka workshop!' \
  'Event-driven architecture rocks' \
  '{"user": "user1", "action": "test"}' \
| oc run kafka-producer -i --rm \
  --image={kafka_cli_image} \
  --restart=Never \
  -n $(oc whoami)-workshop \
  -- bin/kafka-console-producer.sh \
    --bootstrap-server cdc-cluster-kafka-bootstrap.kafka-cdc.svc:9092 \
    --topic test-workshop
----

The command finishes with `pod "kafka-producer" deleted`. A PodSecurity warning on create is expected if the pod still runs and is deleted at the end.

== CLI: Consume Messages

Read the messages back. The consumer stops on its own after five records. Shared topics may also show messages from other participants:

[source,bash,role="execute",subs="+attributes"]
----
oc run kafka-consumer -i --rm \
  --image={kafka_cli_image} \
  --restart=Never \
  -n $(oc whoami)-workshop \
  -- bin/kafka-console-consumer.sh \
    --bootstrap-server cdc-cluster-kafka-bootstrap.kafka-cdc.svc:9092 \
    --topic test-workshop \
    --from-beginning \
    --max-messages 5
----

You should see the messages you produced, including `Hello from the Kafka workshop!`.

== Explore the Kafka Bridge REST API

The Kafka Bridge exposes a REST API for producing messages via HTTP:

[source,bash,role="execute",subs="+attributes"]
----
curl -sk -X POST {bridge_url}/topics/test-workshop \
  -H "Content-Type: application/vnd.kafka.json.v2+json" \
  -d '{"records": [{"value": {"message": "Hello from REST API!", "user": "user1"}}]}'
----

A successful response includes an `offsets` array.
