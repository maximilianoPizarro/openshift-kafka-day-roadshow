=== How the HTTP Sink Works

The `mailpit-http-sink` connector reads from `cdc.public.customers` and `cdc.public.orders` topics. For each message, it sends an HTTP POST to the `cdc-email-transformer` service.

View the connector configuration:

[source,bash,role="execute"]
----
oc get kafkaconnector mailpit-http-sink -n kafka-cdc -o yaml
----

.Expected HTTP Sink connector (reference, not a step)
[source,yaml]
----
apiVersion: kafka.strimzi.io/v1beta2
kind: KafkaConnector
metadata:
  name: mailpit-http-sink
  namespace: kafka-cdc
  labels:
    strimzi.io/cluster: cdc-connect
spec:
  class: io.aiven.kafka.connect.http.HttpSinkConnector
  tasksMax: 1
  config:
    topics: "cdc.public.customers,cdc.public.orders"
    http.url: "http://cdc-email-transformer.kafka-cdc.svc:8080"
----

=== View the Email Transformer

The transformer converts CDC events into formatted HTML emails:

[source,bash,role="execute"]
----
oc logs deployment/cdc-email-transformer -n kafka-cdc --tail=20
----

You should see lines such as `email sent: Created customers ...`.

== View CDC Notifications in Mailpit

Open **Mailpit** (use the *Mailpit* tab, or open this URL):

link:{mailpit_url}[{mailpit_url},window=_blank]

You should see email notifications for every CDC event:

* **Subject:** `CDC Created - customers: Ana Garcia`
* **Body:** An HTML table with all field values from the database row

Each time the simulator inserts or updates a record, a new email appears in Mailpit within seconds. Subjects from other participants appear on the same inbox; that is expected.

== Explore Consumer Groups

A *consumer group* is the name Kafka uses to remember how far a reader got. *Lag* is the number of records not yet read.

View the consumer groups for the CDC pipeline:

[source,bash,role="execute",subs="+attributes"]
----
oc run kafka-groups -i --rm \
  --image={kafka_cli_image} \
  --restart=Never \
  -n $(oc whoami)-workshop \
  -- bin/kafka-consumer-groups.sh \
    --bootstrap-server cdc-cluster-kafka-bootstrap.kafka-cdc.svc:9092 \
    --list
----

Check lag for the Mailpit sink. Its consumer group is `connect-mailpit-http-sink`:

[source,bash,role="execute",subs="+attributes"]
----
oc run kafka-groups -i --rm \
  --image={kafka_cli_image} \
  --restart=Never \
  -n $(oc whoami)-workshop \
  -- bin/kafka-consumer-groups.sh \
    --bootstrap-server cdc-cluster-kafka-bootstrap.kafka-cdc.svc:9092 \
    --describe --group connect-mailpit-http-sink
----

You should see rows for `cdc.public.customers` and `cdc.public.orders` with lag values.

== Deploy Your Own Consumer

Create a simple consumer in your personal namespace:

[source,bash,role="execute"]
----
oc project $(oc whoami)-workshop
----

[source,bash,role="execute",subs="+attributes"]
----
oc run my-consumer -i --rm \
  --image={kafka_cli_image} \
  --restart=Never \
  -- bin/kafka-console-consumer.sh \
    --bootstrap-server cdc-cluster-kafka-bootstrap.kafka-cdc.svc:9092 \
    --topic cdc.public.orders \
    --from-beginning \
    --max-messages 5
----

This reads five messages from the orders topic and exits. You may see rows produced by the simulator or by other participants.
